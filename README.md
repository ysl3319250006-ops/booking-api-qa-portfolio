# 预约接口自动化测试练习

本仓库基于 [Adam Kelm 的 Playwright Restful Booker API Test Automation](https://github.com/adamkelm/playwright-restful-booker-test) 改造，用于学习软件测试。原项目采用 MIT 许可，原作者版权声明见 LICENSE。

## 项目内容

原仓库提供 TypeScript API 封装、测试数据工厂和针对公开练习服务的测试。本次改造新增本地预约接口练习，使用 Node.js 内存模拟服务，不需要数据库或外部账号。

- 覆盖创建、查询、更新、删除预约及删除后查询。
- 验证未授权修改和删除被拒绝，且原记录不变。
- 验证不存在的预约返回 404。
- 每条测试启动独立本地服务和测试数据，结束后关闭。

**验证范围：**本地用例验证接口封装与模拟服务间的请求和响应，不代表真实 Restful Booker 或生产系统的验证结果。上游仓库中的历史测试和缺陷记录不属于本次新增成果。

## 快速开始

需要 Node.js 20 及以上：

```bash
npm ci
npx playwright test tests/portfolio/local-booking.spec.ts
```

本地用例仅测试 HTTP API，不需要安装浏览器。原项目的其他测试访问公共练习服务，运行前请确认测试范围与数据清理方式。

## 测试设计

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 正常流程 | 创建、读取、修改、删除后再次读取 | 数据正确；删除后返回 404 |
| 权限校验 | 不带令牌修改和删除 | 返回 403；原记录不变 |
| 异常查询 | 查询不存在的预约 | 返回 404 |

## 复习问题

1. 为什么测试数据要自己创建？为了避免依赖其他测试或固定 ID。
2. 为什么拒绝操作后还要再次查询？状态码正确不代表数据一定没有被修改。
3. 为什么每个用例启动独立服务？减少数据互相影响，方便重复执行。
4. 模拟服务能证明什么？只能检验本地模拟约定，不能代替真实服务测试。

代码来自开源项目的部分和本次新增的练习应分别说明；建议先亲自运行、阅读并理解代码，再按真实参与情况介绍项目。
